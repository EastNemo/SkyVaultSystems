Security Model

Designed to minimize trust, reduce exposure, and eliminate unnecessary access.

Security Philosophy

SkyVault is built on the assumption that infrastructure will eventually be probed, monitored, or compromised. Our goal is not to prevent access at all costs, but to ensure that access does not translate into usable data.

We design systems so that even a full server breach does not grant decryption capability or access to plaintext files.

Threat Model

  • Malicious third parties gaining access to storage infrastructure
  • Compromised or malicious service operators
  • Legal or administrative requests for stored data
  • Network-level interception of stored files

SkyVault is not designed to protect against compromised client devices, keylogging malware, or user-side operational security failures.

Cryptography

Client-Side Encryption

Encryption is performed locally on the client. Plaintext data is never transmitted or processed by SkyVault servers.

Key Ownership

Private keys are generated and retained on user devices. SkyVault does not store, escrow, or recover private keys.

Post-Quantum Readiness

Hybrid encryption schemes may be used to combine classical and post-quantum algorithms, reducing long-term cryptographic risk.

Authenticated Encryption

Stored data is protected using authenticated encryption to prevent tampering and undetected modification.

Server-Side Limitations

  • No access to private keys
  • No access to plaintext files
  • No ability to decrypt user data
  • No ability to reset encryption state

Servers are treated as untrusted storage endpoints. Security controls assume that server compromise is possible and must not result in data disclosure.

User Responsibility

Because SkyVault does not retain private keys, users are solely responsible for securing their credentials, seed phrases, and devices. Lost keys cannot be recovered by SkyVault.
